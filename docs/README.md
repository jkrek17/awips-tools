# HF Extratropical Low Archive - web page

A static, dependency-free page for browsing and summarizing the hurricane force
extratropical low archive. Plain HTML, CSS and vanilla JavaScript: no build
step, no framework, no CDN, no network requests once the page has loaded (the
map is a hand-rolled Canvas 2D globe, not a tile-based basemap).

## Views

| Tab | What it answers |
|---|---|
| Map | Where the lows went, on a rotatable orthographic globe. Basin selection changes what is plotted and re-centres the view; tracks are coloured by analyzed MSLP along the track, with fix density, first-fix, and peak-intensity as alternate point layers, an optional ocean-currents underlay, a 10-degree graticule, a lat/lon readout under the cursor, and cursor-anchored zoom. |
| Climatology | Events per season, the seasonal cycle, minimum pressure and time-at-HF distributions, 24-hour deepening, and peak intensity against latitude. |
| Events | Every event in a sortable table, with a CSV download of whatever the filters currently select. Per-event data-quality notes (splits, suspect timestamps, QC flags) show in that event's detail drawer rather than in a separate tab. |
| Method | Category codes, how each derived quantity is computed, and the limits of the archive. |

Filters (basin, event type, seasons, months, minimum pressure, explosive
only, free text) apply to every tab at once, including the summary tiles at
the top.

A dedicated "Data quality" tab used to list every repair, flag and drop
row-by-row. It was removed at the archive owner's request: the repairs are a
working record, not a public statement about the archive's reliability. The
report is still generated (see `data/qc-report.txt` below) but is no longer
linked from the page.

## Files

```
index.html              structure only
favicon.svg             site icon; kept at top level (not under assets/) so a
                        relative href="favicon.svg" resolves the same way in
                        the normal docs/ layout and in a --flat, single-
                        directory deploy
assets/app.css          light and dark palettes, base layout and components
assets/charts.css       styling for assets/js/charts.js
assets/globe.css        styling for the #globe canvas and its wrap
assets/js/util.js       payload decoding, formatting, statistics, tooltips
assets/js/charts.js     small SVG chart set (columns, histogram, scatter, trace)
assets/js/globe.js      orthographic globe: projection, graticule, tracks, currents
assets/js/app.js        filter state and rendering
data/hf-lows.js         generated by tools/build_hf_lows.py - window.HF_DATA
data/hf-lows.json       generated by tools/build_hf_lows.py - the same payload
data/qc-report.txt      generated by tools/build_hf_lows.py - plain-text data
                        quality report; not linked from the page (see Views)
data/coastlines.js      generated by tools/build_coastlines.py - Natural Earth
                        110m land polygons, window.HF_COAST
data/currents.js        generated by tools/build_currents.py - OSCAR mean
                        surface current field, window.HF_CURRENTS
```

Everything under `data/` is generated. Do not edit it by hand.

## Previewing locally

```bash
python3 -m http.server 8000 --directory docs
# then open http://localhost:8000/
```

Opening `docs/index.html` straight off disk also works - that is why the data
ships as `.js` files assigning `window.HF_DATA` / `window.HF_COAST` /
`window.HF_CURRENTS` rather than as JSON loaded with `fetch()`, which `file://`
blocks. Nothing on the page needs network access; coastlines and currents are
baked into the data files at build time, not fetched as map tiles.

## Publishing

This directory is published to **two separate places** - see the root
`README.md` for the full picture. In short:

- **GitHub Pages (development preview).** `.github/workflows/pages.yml`
  rebuilds the data from the CSVs committed under `data/hf_lows/` and deploys
  this directory to Pages on every push to `main` (needs
  **Settings > Pages > Source: GitHub Actions** set once; run the workflow
  manually against a branch to preview it before merging). The repo is
  public and the archive CSVs are committed to it intentionally.
- **The NOAA web server (production).** A forecaster copies this code out of
  GitHub by hand and runs `tools/publish.py`, which fetches the sheet
  through the companion Apps Script app in `web/HFArchiveExport/`, rebuilds
  the data, prints a delta report to review, and only then copies this
  directory into the web root. GitHub plays no part in that path - nothing
  on the production server calls back to it.

Because these two builds run independently, they can show different data at
different times. Two things on the page itself say which one you're looking
at: a **"Preview build"** / **"Local build"** marker next to the
"Experimental" badge (shown only on a `*.github.io` or `localhost` host -
silent on production), and the Method tab's build-provenance footnote (build
time, git commit if known, and whether the data was fetched or built from
CSVs on disk).
