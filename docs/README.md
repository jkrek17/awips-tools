# HF Extratropical Low Archive - web page

A static, dependency-free page for browsing and summarizing the hurricane force
extratropical low archive. Plain HTML, CSS and vanilla JavaScript: no build
step, no framework, no CDN at run time (Leaflet is vendored under
`assets/vendor/`).

## Views

| Tab | What it answers |
|---|---|
| Map | Where the lows went. Tracks coloured by minimum central pressure, a gridded hurricane force fix density, first-fix positions, and peak-intensity positions. |
| Climatology | Events per season, the seasonal cycle, minimum pressure and time-at-HF distributions, 24-hour deepening, and peak intensity against latitude. |
| Events | Every event in a sortable table, with a CSV download of whatever the filters currently select. |
| Data quality | Every repair, flag and drop the build made, row by row. |
| Method | Category codes, how each derived quantity is computed, and the limits of the archive. |

Filters (basin, seasons, months, minimum pressure, explosive only, free text)
apply to every tab at once, including the summary tiles at the top.

## Files

```
index.html              structure only
assets/app.css          light and dark palettes, both explicitly chosen
assets/js/util.js       payload decoding, formatting, statistics, tooltips
assets/js/charts.js     small SVG chart set (columns, histogram, scatter, trace)
assets/js/map.js        Leaflet layers, dateline handling, density grid
assets/js/app.js        filter state and rendering
assets/vendor/leaflet/  Leaflet 1.9.4, vendored
data/hf-lows.js         generated - window.HF_DATA
data/hf-lows.json       generated - the same payload
data/qc-report.txt      generated - plain-text data quality report
```

Everything under `data/` is generated by `tools/build_hf_lows.py`. Do not edit
it by hand.

## Previewing locally

```bash
python3 -m http.server 8000 --directory docs
# then open http://localhost:8000/
```

Opening `docs/index.html` straight off disk also works - that is why the data
ships as a `.js` file assigning `window.HF_DATA` rather than as JSON loaded with
`fetch()`, which `file://` blocks. Only the basemap tiles need network access;
without them the tracks, charts and tables still render.

## Publishing

`.github/workflows/pages.yml` rebuilds the data and deploys this directory to
GitHub Pages on every push to `main`. It needs Pages set to
**Settings > Pages > Source: GitHub Actions** once. To publish a preview from a
feature branch, run the workflow manually against that branch.

Alternatively, with no workflow at all: **Settings > Pages > Deploy from a
branch**, branch `main`, folder `/docs`.
