# Setting up a repo for Claude Code

Four files, each enforcing a rule that prose alone does not:

| File | Enforces |
|---|---|
| `CLAUDE.md` | What the agent cannot infer from the code: generated files, single-source modules, pre-push checks, commit style. |
| `.claude/hooks/session-start.sh` | Tests and linters actually run in a fresh web container. |
| `.claude/hooks/guard-generated.sh` | Generated files are regenerated by their tool, never hand-edited. |
| `.claude/settings.json` | Registers both hooks; pre-allows routine read-only and test commands; denies reads of secret files. |

Templates for all four live in `templates/` next to this file. Never copy a
template verbatim: every `{{PLACEHOLDER}}` must be filled or the line removed.

## 1. Detect

Run these from the repo root and keep the output. Do not write anything yet.

```bash
# Existing config - merge with, never overwrite
ls -la CLAUDE.md .claude/ .claude/settings*.json .claude/hooks .claude/skills 2>/dev/null

# Dependency manifests -> what session-start.sh must install
ls package.json pyproject.toml requirements*.txt setup.py Cargo.toml go.mod Gemfile 2>/dev/null
grep -rhoE '^(import|from) [a-zA-Z_]+' --include=*.py . 2>/dev/null | awk '{print $2}' | sort | uniq -c | sort -rn | head -20

# Test and check commands - README is the usual source of truth
grep -nE '^\s*(python3?|node|npm|pytest|cargo|go|make) ' README.md */README.md 2>/dev/null | head -30
ls tests test spec .github/workflows 2>/dev/null

# Generated files: README phrases, build scripts, CI regeneration steps
grep -rniE 'generated|do not edit|never edit|never hand-edit|regenerate' --include=*.md --include=*.yml --include=*.yaml . 2>/dev/null | grep -v node_modules | head -20

# Secrets: gitignored config, token files, env files
cat .gitignore 2>/dev/null
grep -rniE 'token|secret|credential|\.local\.json|\.env' .gitignore README.md 2>/dev/null | head

# Commit style: look at real subjects
git log --format='%s' -30
```

Then read the README(s) for anything the greps missed: single-source modules
that must not be duplicated, deploy commands with a dangerous default, checks
that CI runs which are cheap to run locally.

## 2. Confirm

Present one table to the user and ask them to correct it before writing.
Every row is a value that goes into a template:

| Fact | Detected value |
|---|---|
| Install commands for web sessions | e.g. `pip install numpy`, `npm install -g html-validate@11.15.0` |
| Pre-push checks (in order) | e.g. `python3 tests/foo.py`, `html-validate docs` |
| Generated paths (never hand-edit) | e.g. `flat/`, `docs/data/`, `web/App/Data.gs` |
| Regeneration command per generated path | e.g. `python3 tools/publish.py --deploy flat --flat --yes` |
| Single-source modules | e.g. `Vortex.html` - no page may redefine its functions |
| Secret files (deny reads) | e.g. `tools/publish.local.json`, `~/.clasprc.json` |
| Commands to pre-allow | the test/build/lint commands above, plus `git status/diff/log` |
| Commit style | e.g. one imperative subject line, optional `area:` prefix |
| Dangerous commands with a safe form | e.g. `clasp deploy` must carry `-i <id>` |

Ask two things explicitly:
- Should the generated-file guard **block** hand edits or only **ask**? Default: block for file-edit tools, ask for shell commands that look like writes.
- Anything the agent keeps getting wrong in this repo that belongs in CLAUDE.md?

Wait for the answer. Do not proceed on silence.

## 3. Write

Fill each template. Rules that keep the result useful:

- **CLAUDE.md under one page.** Only what the agent cannot infer. Link to a README or a skill for anything longer than three lines. Delete any template section the repo has no facts for.
- **session-start.sh runs only on the web** (`CLAUDE_CODE_REMOTE=true`), synchronously, idempotently. Prefer `pip install` / `npm install` over `ci` variants so the container cache helps. No async unless the user asks.
- **guard-generated.sh** carries the guarded paths in its `GUARDED` array. Regeneration tools write through Bash and are not blocked; only `Edit`/`Write`/`MultiEdit`/`NotebookEdit` targeting a guarded path are refused, and Bash commands that pair a guarded path with an in-place write (`sed -i`, `>`, `>>`, `tee`) trigger an ask.
- **settings.json**: if one exists, merge into it (arrays append, objects deep-merge). Never drop an existing hook or permission. Pre-allow only read-only and test commands. Deny `Read` on every secret file. Do not allow-list anything that writes outside the repo or hits the network.

If a repo has a repeated multi-step workflow (deploy, data refresh, flat
rebuild), suggest a skill for it but do not write one unprompted; this skill
sets up the baseline only.

## 4. Validate

Every file gets exercised before commit:

```bash
# Hook scripts are executable and parse
chmod +x .claude/hooks/*.sh && bash -n .claude/hooks/*.sh

# settings.json is valid JSON
python3 -c "import json; json.load(open('.claude/settings.json'))"

# session-start installs what it says, and the checks then pass
CLAUDE_CODE_REMOTE=true CLAUDE_PROJECT_DIR=$PWD .claude/hooks/session-start.sh
# then run ONE pre-push check from CLAUDE.md and show it passing

# guard refuses a hand edit and allows a normal one (exit 2 = blocked)
echo '{"tool_name":"Edit","tool_input":{"file_path":"'$PWD'/<a generated path>/x"}}' | .claude/hooks/guard-generated.sh; echo "exit=$?"
echo '{"tool_name":"Edit","tool_input":{"file_path":"'$PWD'/README.md"}}' | .claude/hooks/guard-generated.sh; echo "exit=$?"
```

Report each result honestly. A check that cannot run here (needs a desktop
app, a licensed environment, a network the container lacks) is listed as
not run, with the reason, in CLAUDE.md's pre-push section.

## 5. Commit

One commit containing all four files, subject in the repo's own style.
Tell the user: the SessionStart hook takes effect for everyone once it is on
the default branch; until then only sessions on this branch get it. Point them
at `/fewer-permission-prompts` after a week of use to grow the allowlist from
real transcripts rather than guesses.
